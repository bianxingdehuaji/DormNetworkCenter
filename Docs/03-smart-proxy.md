# 03. 策略路由与透明代理自动化 (Smart-Proxy)

> 💡 **通用性说明**：本节所涉及的透明代理部署、TProxy 流量分流与 DNS 隔离策略基于标准 OpenWrt 系统编写，适用于任何已具备 root 权限并刷入 OpenWrt 的路由器设备。

本节详细介绍如何在 256MB 内存的受限硬件平台（MT7621A / MIPS 架构）上搭建轻量级透明代理服务，实现局域网全屋终端（Windows、macOS、iOS）免安装客户端无感分流，并精细化隔离校园内网资源与公网流量。

## 一、方案选型与受限硬件优化

在小米 CR6608（MediaTek MT7621A，256MB RAM）上运行代理服务，选型必须兼顾**低内存占用**与**低 CPU 负载**：

| 维度 | 方案 A：OpenClash (Meta / Clash 核心) | 方案 B：PassWall (Xray / Sing-box 核心)（推荐） |
| :--- | :--- | :--- |
| **内存开销** | 80MB ~ 130MB（加载大规则集容易挤压系统可用内存） | **25MB ~ 45MB**（极轻量，占用极低） |
| **转发模式** | TUN / Redirect / TProxy | **TProxy (透明代理)** / Redirect |
| **MIPS 适配** | 需指定 `mipsle-softfloat` 内核 | 原生支持架构对应轻量核心 |
| **适用场景** | 适合拥有 512MB 以上内存的高性能路由 | **最适配 256MB 内存的 MIPS 架构嵌入式设备** |

> 📌 **建议**：追求极致稳定和低内存占用首选 **PassWall + Sing-box/Xray**；若习惯图形化规则面板与订阅分流，可选用 **OpenClash**（需裁剪规则集，避免内存溢出引发 OOM 重启）。

---

## 二、运行依赖与核心准备

### 2.1 安装底层内核模块与依赖

通过 SSH 登录 OpenWrt 终端，更新软件源并安装透明代理所需的底层网络转发依赖：

```bash
opkg update
opkg install curl ca-certificates ca-bundle ipset iptables-mod-tproxy kmod-ipt-tproxy
```

### 2.2 核心架构匹配 (MIPS 架构避坑)

联发科 MT7621A 属于 **MIPS 32-bit 小端序架构（mipsel）**，且不包含硬件浮点运算单元：
* **架构标识**：`mipsle` 或 `mipsel`
* **核心选择原则**：如果单独下载内核文件（如 Clash 内核或 Sing-box 二进制包），**必须选择带 `softfloat`（软浮点）标记的版本**（例如 `clash-linux-mipsle-softfloat` 或 `sing-box-linux-mipsle-softfloat`），否则运行时会抛出 `Illegal instruction`（非法指令）并直接崩溃退出。

## 三、部署与配置实操（以 PassWall 为例）

### 3.1 安装插件包

1. 将编译好或社区获取的 `luci-app-passwall` 及其依赖包通过 WinSCP 上传至路由器的 `/tmp/` 目录。
2. 在终端执行批量安装：
   ```bash
   opkg install /tmp/*.ipk
   ```
3. 刷新 OpenWrt 网页管理后台，即可在顶部菜单看到 **服务 (Services) -> PassWall**。

### 3.2 节点导入与分流配置

1. **导入节点订阅**：
   * 进入 **PassWall -> 节点列表**，点击添加订阅或手动添加 Shadowsocks / Vless / Trojan 节点。
   * 保存并更新订阅列表，选用延时与连接质量最佳的主节点。

2. **全局流量转发模式设置**：
   * 进入 **PassWall -> 基本设置**。
   * **TCP 代理模式**：推荐选择 `TProxy`（相比 Redirect 模式性能损耗更低，且原生支持保留源 IP）。
   * **UDP 代理模式**：选择 `TProxy`（接管游戏与实时通信流量）。

## 四、校园网环境冲突规避与 DNS 防污染

在高校或机构局域网中，最常见的代理故障是**“代理开启后校园网认证页面无法打不开、内网选课/教务系统断流”**。本方案通过以下关键策略彻底隔离冲突：

### 4.1 校园内网网段（CIDR）强制直连白名单

进入 **PassWall -> 规则管理 -> 直连/白名单 IP**，追加校园网私网网段与认证网关：

```text
172.30.0.0/16       # 深圳大学校园网核心网段 (包含认证接口 172.30.255.42)
172.16.0.0/12       # 标准私网 B 类保留地址 (校内多校区内网)
10.0.0.0/8          # 标准私网 A 类保留地址 (宿舍楼栋常用内网)
210.39.0.0/16       # 校园网公网分配 IP 段 (按实际情况填写)
```

> 这样配置后，数据包只要目标 IP 属于上述范围，在 `iptables/nftables` 链中会被直接打上 `RETURN` 标记，跳过代理直接由 WAN 口网卡发出，保证认证脚本和校内资源不受任何影响。

### 4.2 校园认证域名白名单

在 **规则管理 -> 直连域名列表** 中，添加校园常用域名：

```text
eportal.szu.edu.cn
szu.edu.cn
auth.szu.edu.cn
```

### 4.3 DNS 解析防污染与分流设计

外部代理默认的 Fake-IP 模式会把所有解析请求映射为虚拟 IP（如 `198.18.0.x`），这会导致校园内网鉴权服务器被错误劫持而无法通信。

* **DNS 过滤模式**：推荐选用 **ChinaDNS-NG** 或 **Dnsmasq + 智能分流**。
* **中国大陆 / 校内内网 DNS**：配置为校园网由 DHCP 分配的真实 DNS 地址（如 `172.30.x.x`）或公共 DNS `119.29.29.29` / `223.5.5.5`。
* **远程过滤 DNS**：使用基于安全协议的 DoH / DoT 上游（如 Cloudflare / Google DNS）。
* **解析行为**：校内域名与国内合规域名全部由校园局域网 DNS 直解，仅境外未解析域名送入远程节点通道，从根本上杜绝域名污染与内网阻断。

## 五、全屋终端免配置验证

保存并启动服务后，处于路由器局域网下的各终端无需单独开启代理软件，测试表现如下：

1. **PC (Windows 11)**：
   * 打开浏览器访问校内教务网（`szu.edu.cn`）与认证页，直连秒开。
   * 访问国际学术检索网站（如 Google Scholar、GitHub），透明代理极速加载。
2. **移动端 (iPhone / Mac)**：
   * 连接 Wi-Fi 即享规则分流，后台无需挂载任何 VPN/小火箭类 App，节省移动端电量。
3. **认证自愈不受干扰**：
   * 触发上一节的 `szu_auth.sh` 脚本，探测与鉴权请求全部沿 direct 白名单通道直接送达 `172.30.255.42`，保持断网自愈正常生效。
