# 03. 策略路由与透明代理自动化 (ShellCrash 方案)

> 💡 **通用性说明**：本节所涉及的透明代理部署、TProxy 流量分流与 DNS 隔离策略基于标准 OpenWrt 系统编写，适用于任何已具备 root 权限并刷入 OpenWrt 的路由器设备。

本节详细介绍如何在 256MB 内存的受限硬件平台（MT7621A / MIPS 架构）上，摒弃臃肿的图形化插件，采用极轻量级的 **ShellCrash** 脚本搭建透明代理服务，实现局域网全屋终端（Windows、macOS、iOS）免安装客户端无感分流。

## 一、方案选型与受限硬件优化

在小米 CR6608（MediaTek MT7621A，256MB RAM）上运行代理服务，选型必须兼顾**极低内存占用**与**低 CPU 负载**：

| 维度 | OpenClash (常规插件) | PassWall | **ShellCrash (最终极选型)** |
| :--- | :--- | :--- | :--- |
| **内存开销** | 80MB ~ 130MB (极易 OOM 死机) | 25MB ~ 45MB | **约 10MB ~ 20MB (极致轻量)** |
| **运行机制** | 依赖复杂 LuCI 网页后台 | 依赖 LuCI 网页后台 | **纯 Shell 脚本驱动，零 GUI 负担** |
| **面板管理** | 强制内置 | 无现代面板 | **可挂载 Metacubexd，纯前端渲染** |
| **适用场景** | 高端 x86 软路由 | 普通硬路由 | **受限内存 MIPS 路由器的最优解** |

> 📌 **建议**：追求极致稳定和低内存占用，绝对首选 **ShellCrash + Meta 内核**组合。它摒弃了 OpenWrt 传统的网页插件包，直接在系统底层运行，把宝贵的内存全留给网络并发处理。

## 二、部署 ShellCrash 与内核选择

### 2.1 一键安装 ShellCrash
通过 SSH 登录 OpenWrt 终端，执行官方一键安装命令：

```bash
export url='https://fastly.jsdelivr.net/gh/juewuy/ShellCrash@master' && sh -c "$(curl -kfsSl $url/install.sh)" -s mac
```
*选择 `1` (安装到 /etc 目录) 即可，占用极小。*

### 2.2 核心架构匹配 (MIPS 架构避坑)
联发科 MT7621A 属于 **MIPS 小端序架构**，安装完毕后输入 `crash` 进入主菜单配置内核：
1. 进入 `9` (更新/卸载) -> `1` (更新核心)。
2. **架构选择**：必须选择 **`mipsle`** 或 **`mipsel`**。
3. **浮点运算**：强烈建议选择带 `softfloat` (软浮点) 的正式版 Release 内核，兼容性最稳，有效避免 `Exec format error` 崩溃。

## 三、订阅导入与面板安装

### 3.1 导入机场订阅与生成策略组（生成策略组是可选操作）
1. 在 `crash` 菜单中输入 `6` (导入配置文件) -> `1` (在线生成 Meta 配置文件)。
2. 粘贴机场订阅链接，并选择 **ACL4SSR_Online_Full** 或 **全分组** 模板。
3. 这种方式会让云端服务器自动帮你按国家 (如 美国节点) 和服务 (如 Netflix、OpenAI) 生成完美的策略组，省去手动编写规则的麻烦。

### 3.2 安装 Metacubexd 管理面板
为了方便在电脑/手机上切换节点，我们需要安装一个零负担的纯静态面板：
1. 终端进入 `crash` -> `9` (更新/卸载) -> `4` (安装/切换 Web 面板)。
2. 选择 **Metacubexd** 进行安装。
3. **使用方法**：在电脑浏览器打开 `http://192.168.1.1:9999/ui`，将其“创建为应用快捷方式”放到桌面，即可像原生软件一样丝滑管理网络。

## 四、校园网环境冲突规避与精准分流

在高校局域网中，最怕代理软件劫持内网流量，导致“校园网认证打不开”或“教务系统断连”。ShellCrash 对此有着极佳的防御机制：

### 4.1 内网私有 IP 自动直连 (绕过局域网)
ShellCrash 默认开启了“绕过局域网 IP”功能。当访问目标为以下校园网常见私有网段时，流量会自动被打上 `RETURN` 标记，直接走物理 WAN 口直连：
* `172.30.0.0/16` (深大校园网核心网段与认证接口)
* `172.16.0.0/12` & `10.0.0.0/8` (宿舍与多校区内网)

### 4.2 校园认证域名与特定服务强制白名单
对于需要强制直连的校园公网域名，或需要强制走特定节点的 AI 服务（如 Gemini），我们通过修改配置文件实现：
1. 使用 WinSCP 编辑 `/etc/ShellCrash/yaml/user_rule.yaml`。
2. 写入自定义分流规则：
```yaml
# 校园网认证与教务系统强制直连 (DIRECT)
- DOMAIN-SUFFIX,szu.edu.cn,DIRECT
- DOMAIN-SUFFIX,eportal.szu.edu.cn,DIRECT

# 敏感 AI 服务强制走纯净节点 (规避地区限制)
- DOMAIN-KEYWORD,gemini,🇺🇸 美国节点
- DOMAIN-SUFFIX,gemini.google.com,🇺🇸 美国节点
```
3. 终端执行 `crash` -> `1` 重启服务生效。

## 五、全屋终端免配置验证

保存并启动 ShellCrash 后，处于路由器局域网下的各终端无需单独开启任何代理软件，测试表现如下：

1. **PC (Windows 11) / NAS**：
   * 打开浏览器访问校内教务网与认证页，直连秒开。
   * 校园网 SMB 内网穿透/局域网共享读写完全不受代理干扰。
2. **移动端 (iPhone / Mac)**：
   * 连接 Wi-Fi 即享规则分流，后台无需挂载任何 VPN/小火箭类 App，大幅节省移动端电量。
3. **认证自愈不受干扰**：
   * 触发上一节的 `szu_auth.sh` 守护脚本时，探针与鉴权请求全部沿底层白名单通道直达 `172.30.255.42`，保持断网自愈稳定运行。
